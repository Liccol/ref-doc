# 2026 年 10 月 29 日至 11 月 4 日 Tool Calling 变更记录

## 新特性与能力扩展

### Rust 前端支持 Responses API

Rust 前端新增 `/v1/responses` 的流式与非流式执行，并以流式事件为主路径、非流式结果由事件折叠生成；function tools 可随请求传入并回显，历史 input 会完整重放。当前 `store: true` 只接受参数但不持久化，`background`、`previous_response_id`、检索/取消、内置工具、custom/namespace tools、`allowed_tools` 和 output logprobs 尚不支持；`max_tool_calls` 也只预留给尚未支持的内置工具。该变更不要求修改 tool parser 参数，但只有启用 Rust 前端时生效，不能把 Python Responses API 的全部能力直接视为已对齐。[#63902](https://github.com/vllm-project/vllm/pull/63902)

### Mistral 工具调用改用统一 grammar

Mistral parser 改用 `mistral-common>=1.13.0` 的 `get_grammar_for_chat_request`：`required` 与命名调用可直接约束必须调用/指定函数，`auto` 可在普通回答、JSON 回答和工具调用间选择，`json_schema.strict=true` 才按 schema 约束，非 strict 只保证任意 JSON 对象或数组；缺少 schema 会返回 400，`parallel_tool_calls: null` 可接受。存量 `--tool-call-parser mistral` 命令无需调整，但环境必须满足新的 mistral-common 版本。作者只完成 CPU grammar/解析测试，没有真实模型 GPU 端到端验证。[#64169](https://github.com/vllm-project/vllm/pull/64169)

### GLM-5.3 原生 Rust renderer

新增支持 tools 与 reasoning 的 GLM-5.3/GLM-5.3-Flash Rust renderer。`glm5_next` 模型类型（GLM-5.3-Flash）可自动选择；GLM-5.3 需增加 `--tokenizer-mode glm5_next`。`tool_choice=none` 默认仍把 tools 放进模板，只有显式使用 `--exclude-tools-when-tool-choice-none` 才排除。该能力只属于 Rust renderer，Python/HF renderer 行为不变；PR 给出前端 benchmark，没有真实模型 GPU 评测。[#62424](https://github.com/vllm-project/vllm/pull/62424)

### Granite 4.2 tool parser

新增 `granite_toolcall_parser`，解析 Granite 4.2 的 `<tool_call><function=...>` 格式，可与 `granite_thinking_parser` 组合，也支持关闭 thinking。启用方式为 `--enable-auto-tool-choice --tool-call-parser granite_toolcall_parser`；作者提供 parser 测试，未声明真实 Granite 4.2 服务端到端验证。[#65216](https://github.com/vllm-project/vllm/pull/65216)

## 兼容性修复

| 日期 | 类型 | 变更与边界 | 来源 |
| --- | --- | --- | --- |
| 10-29 | Responses thinking budget | Responses API 开始把 `thinking_token_budget` 传给模板；`-1` 表示不限，其他负数按 400 拒绝，不再静默丢弃。适用于支持该模板参数的模型，存量启动命令无需调整 | [#63896](https://github.com/vllm-project/vllm/pull/63896) |
| 11-02 | Responses 历史规范化 | incomplete assistant/reasoning 项及只有工具调用、没有文本的 turn 可规范化后重放，减少客户端继续会话时的校验失败 | [#35508](https://github.com/vllm-project/vllm/pull/35508) |
| 11-02 | Mistral special token | Responses 与 legacy Mistral parser 保留 `skip_special_tokens` 配置，避免迁移统一渲染链路后改变 checkpoint 的 special-token 输出 | [#65118](https://github.com/vllm-project/vllm/pull/65118) |
| 11-03 | parser prompt 上下文 | derender parser 可收到调用方原始 `prompt_token_ids`，为依赖 prompt 状态的 parser 提供一致上下文；现有 parser 启动参数不变 | [#63434](https://github.com/vllm-project/vllm/pull/63434) |
| 11-04 | Python 空工具列表 | Python 前端把 `tools: []` 视为没有工具：省略/`none`/`auto`/`required` 均可继续普通生成，命名函数仍返回 400。Rust 前端本期仍按 [#63060](https://github.com/vllm-project/vllm/pull/63060) 拒绝空列表，两个前端暂不一致 | [#65547](https://github.com/vllm-project/vllm/pull/65547) |
| 11-04 | Rust assistant 历史 | Rust 前端允许 assistant 历史的 `content` 缺省、`null` 或 `[]` 且没有 tool calls，和 Python 的历史重放行为对齐 | [#64492](https://github.com/vllm-project/vllm/pull/64492) |

| 11-04 | Step3 schema coercion | 支持 nullable，并按 schema 对 object/array 参数做一致转换 | [#65274](https://github.com/vllm-project/vllm/pull/65274) |
| 11-04 | Kimi K3 流式扫描 | 改为增量扫描工具调用标记，减少长流中重复遍历和 chunk 边界问题；启动参数不变 | [#62203](https://github.com/vllm-project/vllm/pull/62203) |
