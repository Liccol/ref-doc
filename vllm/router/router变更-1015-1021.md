# 2026 年 10 月 15 日至 21 日 vLLM Router 与 SGLang Model Gateway 变更记录

## vLLM Router

### 新特性与行为变更

| 日期 | 特性 | 变化与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-15 | 限流重试提示 | 并发 token 不足且队列关闭或已满时，429 响应新增 `Retry-After` 秒数；数值按当前 token 缺口和 refill rate 向上取整、最少 1 秒，正在结束的请求可能让容量更早释放 | [#281](https://github.com/vllm-project/router/pull/281) |
| 10-19 | KV-aware 成本路由 | 新增 opt-in `--policy kv_aware`，把 vLLM KV event 提供的多层驻留区间与 `(worker, dp_rank)` 实时 prefill token/请求负载组合，按 `ptoken × (batchsize + 1)` 选择目标；支持温度采样及 HostPinned/External/Disk credit 参数。当前限常规 co-located 路由，不包含完整 E/P/D、容量过滤和专用指标；缺少 token IDs 或发现数据时退化为负载选择，不把未知前缀当作命中 | [#371](https://github.com/vllm-project/router/pull/371) |
| 10-21 | gRPC L0 命中少拷贝 | L0 编码缓存改存 `Arc<[u32]>`，命中时与 `PreparedChat` 共享同一份 token IDs，避免长 prompt 的两次复制和分配；沿用 `VLLM_ROUTER_L0_CACHE=1`，缓存语义不变 | [#389](https://github.com/vllm-project/router/pull/389) |

### 问题修复与性能

| 日期 | 问题 → 修复后行为 | 来源 |
| --- | --- | --- |
| 10-15 | PD prefill 请求只把 `max_tokens` 设为 1，但 `min_tokens=0` 时首个 token 可采到 EOS/stop，导致 prefill 阶段提前结束 → Chat/Completions 与 Generate prefill 请求统一把 `min_tokens` 设为 1；Responses API 仍只使用 `max_output_tokens=1` | [#360](https://github.com/vllm-project/router/pull/360) |
| 10-17 | `cache_aware` 的负载统计包含已不健康 worker，可能用失效节点的计数扭曲健康候选选择 → 统计和候选过滤统一忽略不健康 worker | [#319](https://github.com/vllm-project/router/pull/319) |
| 10-19 | TokenBucket 高频路径使用 Tokio async mutex，临界区没有 await 却承担调度开销 → 改用 `parking_lot::Mutex`；限流容量与排队语义不变 | [#385](https://github.com/vllm-project/router/pull/385) |
| 10-20 | 代理型 GET endpoint 仍可能转发到不健康 worker → 仅从健康 worker 中选择；没有健康候选时返回服务不可用，而不是向已知失效节点发送请求 | [#232](https://github.com/vllm-project/router/pull/232) |

## SGLang Model Gateway

### 新特性与问题修复

| 日期 | 类型 | 变更与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-17 | 构建修复 | 删除未使用的 `npyz` dev dependency，规避其依赖版本被撤回后导致 Gateway 构建失败；运行时路由行为不变 | [#44720](https://github.com/sgl-project/sglang/pull/44720) |
| 10-20 | PD decode 调度窗口 | 新增 `--decode-dispatch-limit N`：请求仍会立即发往 prefill，但每个 prefill worker 最多让 N 个请求同时继续派往 decode；其余请求按到达顺序等待，并在放行时才选择 decode worker，避免长 prefill 队列让过早选定的 decode worker 负载失真。只在显式设置时生效，值必须大于 0；prefill engine 还需把 `--optimistic-prefill-attempts` 设为大于 0 | [#44689](https://github.com/sgl-project/sglang/pull/44689) |
