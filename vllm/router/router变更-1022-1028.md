# 2026 年 10 月 22 日至 28 日 vLLM Router 与 SGLang Model Gateway 变更记录

## vLLM Router

### 新特性与行为变更

| 日期 | 特性 | 变化与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-24 | gRPC Completions | gRPC worker pool 新增 `/v1/completions`，只接受 token-ID 数组 prompt，跳过 router tokenizer/chat template，并按 Completions 形状返回流式或非流式响应；文本 prompt、负数 ID、未知扩展和不支持的 `suffix`、`best_of`、`echo` 等返回 400。无需新 CLI 参数，HTTP pool 与 gRPC Chat 不变 | [#409](https://github.com/vllm-project/router/pull/409) |
| 10-27 | gRPC L1 前缀编码缓存 | 设置 `VLLM_ROUTER_L1_CACHE=1` 后，Rust gRPC Chat 可从边界安全的 radix tree 复用历史 prompt token IDs，只编码新增尾部；可与 L0 同开，完整命中先走 L0。仅覆盖 token IDs 路径，HTTP、tiktoken/tekken 和无法证明边界安全的 tokenizer 不启用；`VLLM_ROUTER_L1_VERIFY=1` 可用完整重编码校验并在不一致时禁用 L1 | [#374](https://github.com/vllm-project/router/pull/374) |
| 10-27 | KV-aware session affinity | co-located `kv_aware` 新增 `--kv-aware-session-affinity-ttl-secs 1..31536000`，根据 agent/session header 或请求身份把后续 turn 软绑定到原 worker；无身份、过期、worker 不健康、重试排除或 10,000 条容量耗尽时回退 KV/load 评分。默认关闭，绑定是 router 本地状态，多副本还需入口粘性 | [#392](https://github.com/vllm-project/router/pull/392) |
| 10-28 | KV-aware 扩展至 PD | P/D 模式允许分别设置 `--prefill-policy kv_aware --decode-policy kv_aware`：P 按多层 KV credit 与已接纳 prefill 工作选择，D 按 pending+active 占用选择；可配同一 affinity TTL 保持顺序 session 的 decode 位置。当前 KV credit 仅 HTTP，D 不查询 placement index，未增加 KV 容量硬过滤 | [#386](https://github.com/vllm-project/router/pull/386) |
| 10-28 | Program-scoped PD 调度 M1 | Program scheduling 配置新增 opt-in `pd.enabled`：识别 `vllm_xargs.agentic_context` 的多 turn Program，优先复用同一 decode engine/DP rank，按 D 容量接纳，并用每个 P 的 permit 限制并发 prefill；无 Program 身份或未开启时继续原生 PD。默认 Acting TTL 为 0，仅保留 affinity 供下次重新接纳；显式 TTL 也只是 router 逻辑预留，不保证跨 turn KV 物理驻留 | [#388](https://github.com/vllm-project/router/pull/388) |

### 问题修复与性能

| 日期 | 问题 → 修复后行为 | 来源 |
| --- | --- | --- |
| 10-25 | user message 的 `audio_url`、`input_audio`、`video_url` 等未知 content part 会让 typed 反序列化回退为空字符串并静默丢失输入 → HTTP 路径以原始 JSON parts 保存和转发；token-ID-only gRPC 仍只接受文本 part | [#327](https://github.com/vllm-project/router/pull/327) |
| 10-25、10-26 | `Connection` 指定的 hop-by-hop header 及非标准 `Proxy-Connection` 可能穿透请求/响应转发 → regular、transparent、PD 等路径统一剔除，同时保留 Content-Encoding、Set-Cookie 等端到端字段；旧 GET 字符串辅助路径仍不能保留非 UTF-8 header 值 | [#358](https://github.com/vllm-project/router/pull/358)、[#456](https://github.com/vllm-project/router/pull/456) |
| 10-27 | token-array 按长度、普通 chat 按 session/空 key 做 `cache_aware`，无关请求会误判前缀且增长对话失去 affinity → 用完整 token/prompt 内容和稳定 tool schema 建 key，只对完整前缀计算命中；显式 session 仍精确匹配，per-worker/model 字符预算统一为 `2^25` | [#454](https://github.com/vllm-project/router/pull/454) |
| 10-27 | PD decode 在 prefill 完成前不计入本地 load，连续请求可能集中选中同一 D → selection 与 reservation 原子化，并让 Chat、Completions、Responses 在 prefill 等待期间持有 decode load guard；本次不解决流式 header 后释放、prefill 取消或分布式 admission | [#373](https://github.com/vllm-project/router/pull/373) |
| 10-27 | PD 的 Decode 会把传入 KV 报为自身 cache hit，且 P/D input count 不一致，导致最终 usage 错算 → JSON/SSE 统一使用 Prefill 的 input/cache 数据与 Decode 的 output 数据重算 totals，并保留 Decode 非 2xx 状态、body 和 headers；重写仅处理受支持大小且未编码的 JSON/SSE，超限或编码 body 原样透传 | [#382](https://github.com/vllm-project/router/pull/382) |
| 10-28 | worker 注册后若健康状态一直不变，`vllm_router_worker_health` 不会出现初始值 → 注册时立即发布各 DP rank 当前健康度；worker 删除后的旧 metric series 仍不会清理 | [#274](https://github.com/vllm-project/router/pull/274) |
| 10-28 | Kubernetes pod 变为 `Ready=False` 或 label 不再匹配 selector 时，只要 HTTP `/health` 仍为 200 就继续接流量 → watch 事件按 pod identity 更新并立即 deregister，不再等待 HTTP 健康检查阈值 | [#379](https://github.com/vllm-project/router/pull/379) |
| 10-28 | Chat JSON parser 会复制 message 字段，Rust gRPC 每个 SSE frame 又做一次字符串复制 → 从临时 JSON 中移动字段并直接写入单一 SSE buffer，HTTP/gRPC 响应字节与协议不变；作者只声明 router CPU/分配减少，不代表模型吞吐已验证 | [#449](https://github.com/vllm-project/router/pull/449) |

## SGLang Model Gateway

本期 `sgl-model-gateway/` 未发现新特性、行为变更或问题修复。
