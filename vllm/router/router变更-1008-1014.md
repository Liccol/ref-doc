# 2026 年 10 月 8 日至 14 日 vLLM Router 与 SGLang Model Gateway 变更记录

## vLLM Router

### 新特性与行为变更

| 日期 | 特性 | 变化与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-08 | 多层 KV 放置索引基础 | 新增从 vLLM KV 事件维护 `(owner, tier)` 驻留信息的 radix-tree 索引，可按 Device、HostPinned、Disk、External 查询目标；本次只有索引模块，没有 CLI 开关和路由策略消费者，现有 `cache_aware` 行为不变 | [#326](https://github.com/vllm-project/router/pull/326) |
| 10-12 | EPD 路由 | 新增 `--epd-config`，支持 E+PD / E/P/D 编排：媒体分发给 Encoder，路由器只转发 JSON 元数据，embedding 传输仍由 Mooncake/NIXL 等 EC 后端完成。当前限原生 CLI、静态 worker、DP=1，并依赖 vLLM 的 JSON metadata 支持 | [#266](https://github.com/vllm-project/router/pull/266) |
| 10-13 | gRPC L0 编码缓存 | 设置 `VLLM_ROUTER_L0_CACHE=1` 后，完整重复 prompt 可复用 token IDs；按 tokenizer、special-token 设置和 `cache_salt` 隔离。token-ID prompt 不进入缓存，超大编码使用但不缓存，重试复用已准备的 IDs | [#340](https://github.com/vllm-project/router/pull/340) |
| 10-13 | KV tier 查询契约 | `TierMatch` 从单一连续前缀深度改为返回多个半开区间 `segments`，使 Host/Disk 仅持有被逐出的尾部块时仍可被上层成本模型看到；本次没有增加成本模型策略 | [#370](https://github.com/vllm-project/router/pull/370) |
| 10-14 | KV 事件严格解码 | 新增批事件严格解码、设备事件形状和静态 endpoint 校验，拒绝未知/重复字段、错误 wire type、超限 payload 等；当前公开的是 ingestion helper，运行时 subscriber 接入仍是后续工作 | [#352](https://github.com/vllm-project/router/pull/352) |

### 问题修复

| 日期 | 问题 → 修复后行为 | 来源 |
| --- | --- | --- |
| 10-08 | 长字符串 prompt 在 untagged enum 中依次尝试数组类型，CJK 约 1 MiB 解析可耗时约 200 ms → 先尝试唯一可匹配的 String 变体；数组 prompt 的判定顺序不变 | [#325](https://github.com/vllm-project/router/pull/325) |
| 10-08 | JSON Schema 和工具参数的属性顺序依赖传递依赖偶然启用 `serde_json/preserve_order` → Router 直接声明该特性并加入回归测试；当前 main 的实际转发行为不变，但去除了依赖耦合 | [#334](https://github.com/vllm-project/router/pull/334) |
| 10-08 | HTTP Chat 请求遇到 `latest_reminder` 等模型专属 role 会被 Router 拒绝 → HTTP 路径原样保留未知 role 与扩展字段；gRPC 的 `vllm-chat` 尚不能表示任意 role，仍明确拒绝 | [#301](https://github.com/vllm-project/router/pull/301) |
| 10-08 | keep-alive SSE 首个 chunk 可能被 Nagle 算法延迟并与后续 chunk 一起突发 → client-facing socket 设置 `TCP_NODELAY` | [#314](https://github.com/vllm-project/router/pull/314) |
| 10-08 | Router 接受文档范围外的 `top_p=0` → 按 `(0, 1]` 校验并在转发前拒绝 | [#303](https://github.com/vllm-project/router/pull/303) |
| 10-12 | 删除某用户最后一条内存 response 后仍保留空索引，`stats()` 的 user count 偏大 → 删除空用户索引 | [#300](https://github.com/vllm-project/router/pull/300) |
| 10-12、10-13 | KV radix 压缩边中途分叉会把不连续块误算为连续命中；多个 owner 对同一路径使用不同 engine hash 时移除/父节点定位可能错误 → 只在完整匹配当前边后下钻，并为共享路径保留各 owner 的实际 hash 身份 | [#366](https://github.com/vllm-project/router/pull/366)、[#357](https://github.com/vllm-project/router/pull/357) |

## SGLang Model Gateway

### 新特性与问题修复

| 日期 | 类型 | 变更与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-13 | DP-aware `power_of_two` 修复 | DP worker 从 URL 展开时不再按 URL 数量错误拒绝 1P1D/2P1D；每个 engine 只拉取一次 `/v1/loads` 并按 `dp_rank` 映射 token load，失败时回退请求数，PD 流式请求从 dispatch 起计为 in-flight。`power_of_two` 在 DP-aware decode 下由随机近似恢复为按实际负载比较 | [#42027](https://github.com/sgl-project/sglang/pull/42027) |
| 10-13 | P2C 请求数负载策略 | 新增环境变量 `SGLANG_ROUTER_P2C_LOAD_METRIC`：`tokens` 保持默认；`requests` 在两个候选间比较实时 in-flight 请求数；`least_requests` 比较全部候选。仅作用于 `--dp-aware` decode 的 power-of-two 选择；并发选择读取无锁，仍可能同时选中同一 worker | [#43483](https://github.com/sgl-project/sglang/pull/43483) |
