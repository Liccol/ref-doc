# MiniMax CLI 变更记录（2026-10-15 ～ 2026-10-21）

## 新特性与行为变化

| 日期 | 特性 | 变化与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-19 | M3.1 正式模型名与精简目录 | `MiniMax-M3.1-Flash-Preview` 全面更名为 `MiniMax-M3.1-Flash`；Agent setup 的可选模型收敛为 M3.1 Flash 与 M3，按量付费 key 的默认 setup 模型也改为 M3.1 Flash。显式旧 Preview 名称的已有配置需要改名；普通 `text chat`/SDK 的显式模型选择仍优先 | [#293](https://github.com/MiniMax-AI/cli/pull/293)、[#294](https://github.com/MiniMax-AI/cli/pull/294)、[#296](https://github.com/MiniMax-AI/cli/pull/296) |
| 10-19 | Zed Agent 配置 | `mmx agent setup` 新增 Zed 支持，检测或安装 Zed 后写入其 agent/model provider 配置，并沿用现有 China/Global credential 与备份流程 | [#297](https://github.com/MiniMax-AI/cli/pull/297) |

## 问题修复

| 日期 | 问题 → 修复后行为 | 来源 |
| --- | --- | --- |
| 10-16 | 多个并发请求发现 OAuth access token 过期时会各自刷新，可能相互覆盖 credential 或重复请求 → 同一 credential 的自动刷新合并为一个进行中的任务，其他调用复用结果 | [#291](https://github.com/MiniMax-AI/cli/pull/291) |
| 10-16 | OAuth resource URL 会从通用 API host 推导，China/Global 或自定义 host 下可能读取错误资源键 → resource URL 绑定到实际 OAuth credential 配置 | [#284](https://github.com/MiniMax-AI/cli/pull/284) |
| 10-16 | polling 在截止时间前按固定间隔 sleep，剩余时间小于间隔时会越过 deadline → sleep 上限改为剩余时长，超时返回更及时 | [#283](https://github.com/MiniMax-AI/cli/pull/283) |
| 10-19 | Oh my Pi 的 M3.1 Flash 配置没有发送 low/medium/high effort；Pi/OpenCode 还会携带不适用的 temperature → 声明 MiniMax 原生 effort 档位并移除 temperature，OMP 三档 effort 可进入请求 | [#295](https://github.com/MiniMax-AI/cli/pull/295)、[#298](https://github.com/MiniMax-AI/cli/pull/298) |
