# MiniMax Code 特性变更总结（2026-09-28 ～ 2026-10-12）

本期重点是**对话与任务交互扩展、模型请求可靠性、后台任务生命周期和 TUI 稳定性**。新增轻量对话与启动级提示覆盖，改进侧会话操作；修复图片超限、请求挂起、压缩后身份丢失等问题。


## 新特性与能力扩展

| 日期 | 特性                         | 变化与使用边界 | 来源 |
| --- |----------------------------| --- | --- |
| 09-28、10-01 | M3.1 Flash Preview 接入与默认模型调整 | 首次安装的 fallback catalog 加入 `MiniMax-M3.1-Flash-Preview`；随后将未选模型时的默认值切到该模型。既有官方目录快照仍优先，不能理解为强制覆盖所有已配置模型 | [#375](https://github.com/MiniMax-AI/minimax-code/pull/375)、[#421](https://github.com/MiniMax-AI/minimax-code/pull/421) |
| 09-29 | 后台任务计数                     | 状态行新增 `background=N`，显示当前根会话活跃后台任务 | [#398](https://github.com/MiniMax-AI/minimax-code/pull/398) |
| 09-29 | Worktree 与编辑器扩展            | 默认在创建 worktree 前 fetch 所选上游；fork 工作区指纹排除嵌套根。外部编辑器目录加入 Ghostty | [#398](https://github.com/MiniMax-AI/minimax-code/pull/398) |
| 10-06 | 轻量对话模式                     | TUI / exec 新增 `--mode lightweight`，使用精简提示且不提供工具，不能读写项目文件。模式在根会话创建时固定；该参数不能与 `--session` / `--continue` 合用，已有轻量会话可正常重新打开 | [#436](https://github.com/MiniMax-AI/minimax-code/pull/436) |
| 10-09 | SOCKS5 代理                  | 支持 `socks5://`、`socks5h://`、`socks://`，保留 `NO_PROXY` 直连。不支持或畸形的 `ALL_PROXY` 改为脱敏警告后忽略，避免启动崩溃；显式错误的 `HTTP_PROXY` / `HTTPS_PROXY` 仍报错 | [#465](https://github.com/MiniMax-AI/minimax-code/pull/465) |

## 问题修复与行为变化

### Agent、模型请求与任务状态

| 日期 | 主题                  | 问题 → 修复后行为 | 来源 |
| --- |---------------------| --- | --- |
| 09-28 | 停止后台任务行为调整          | 显式停止会话会级联取消所属后台 Bash / 子 Agent。切换会话或 `/clear` 只停止前台并暂停 Goal/队列，后台继续运行 | [#381](https://github.com/MiniMax-AI/minimax-code/pull/381) |
| 09-29 | 中断后的编辑与回退           | 中断后历史仅留下隐藏后台提醒时，仍允许编辑或 rewind；减少会话文件列表和长历史导航的读取开销 | [#398](https://github.com/MiniMax-AI/minimax-code/pull/398) |
| 10-01 | Goal 最终回复           | 接受 `update_goal(status=complete)` 后，保留同一 turn 生成最终交付回复，再由宿主验证；接受提案后拒绝后续工具调用。最终回复为空允许补写一次，并不保证最终一定有非空回复 | [#421](https://github.com/MiniMax-AI/minimax-code/pull/421) |
| 10-01 | 压缩请求兼容              | OpenAI 兼容压缩请求省略空 `tools`，避免 400；continuation 没有当前用户消息时，将压缩后的提醒放在尾部，避免反复中止和重新压缩 | [#199](https://github.com/MiniMax-AI/minimax-code/pull/199)、[#421](https://github.com/MiniMax-AI/minimax-code/pull/421) |
| 10-04 | 挂起请求与流空闲超时          | 每次物理模型请求增加首事件和流空闲时限，**最终默认均为 300 秒**，用户取消仍独立处理。无可见输出时可按原策略重试；已输出后超时结束该轮，不自动重试 | [#428](https://github.com/MiniMax-AI/minimax-code/pull/428) |
| 10-05 | 图片超限与会话恢复           | 单请求默认保留最新 20 张图片，可按模型设置更低上限；较旧图片仅在请求副本中替换为提示，存储历史不改写。确定性图片/400 拒绝不反复重试；压缩遇图片超限可退到无图片候选 | [#431](https://github.com/MiniMax-AI/minimax-code/pull/431) |
| 10-08 | Ask / Plan 等待状态     | `ask_user` 已产生持久待回答请求、却没有最终回复时，状态改为等待用户继续，避免误报可重试的 `EMPTY_RESPONSE` | [#444](https://github.com/MiniMax-AI/minimax-code/pull/444) |
| 10-08 | 一次性定时任务             | 修复 `cron once --after 1w` 被拒绝：`1w` 是一周后执行一次，`1w2d` 是九天后；不是每周重复。**`1week` 不支持**。同时修复长无效数字输入导致的解析耗时问题 | [#435](https://github.com/MiniMax-AI/minimax-code/pull/435) |
| 10-09 | 上下文提醒精简             | 执行预算提醒改为首次、预算阈值和最后两分钟等必要时机；时间改为分钟精度，已有会话 ID 时不重复写入。不是所有提醒都改成“每轮仅一次” | [#459](https://github.com/MiniMax-AI/minimax-code/pull/459) |
