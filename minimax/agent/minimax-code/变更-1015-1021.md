# MiniMax Code 特性变更总结（2026-10-15 ～ 2026-10-21）

## 新特性与能力扩展

| 日期 | 特性 | 变化与使用边界 | 来源 |
| --- | --- | --- | --- |
| 10-15 | Google BYOK | CLI/TUI 的手工 provider 配置新增 `google-generative-ai`，模型请求和连接探测复用 Pi Google adapter；覆盖 OpenCode Go Gemini 4，并为其 `/inference/go` 请求附加 conversation headers。没有新增原生模型发现，需由用户配置 provider；作者报告完成真实 OpenCode Go 连接和文件工具往返，Windows/Linux 留给 CI | [#492](https://github.com/MiniMax-AI/minimax-code/pull/492) |
| 10-15 | Plugin V1 公开契约与校验器 | 公开 Plugin V1 格式、五类 JSON Schema、digest 参考向量和零依赖 `tools/plugins/validate-plugin.mjs`，外部作者可运行 `pnpm check:plugin` 做与公开 CI 同源的本地校验。catalog 成员资格、跨文件 capability 闭合、archive 上限和最终 `content_digest` 仍由官方 Marketplace 提交端校验 | [#484](https://github.com/MiniMax-AI/minimax-code/pull/484) |
| 10-19 | 自动压缩阈值 | `config.yaml` 新增 `contextManagement.compactionTriggerAt`：`(0,1]` 表示 context window 比例，大于 1 的整数表示 token 数；有效阈值与内置阈值取较小值，因此只能提前自动压缩。非法数字或配置读取失败会记录并回退；设置低于压缩后大小会导致几乎每次请求前都压缩 | [#493](https://github.com/MiniMax-AI/minimax-code/pull/493) |
| 10-19 | M3.1 Flash 默认模型 | 内置 MiniMax fallback catalog 和 managed preset 默认值从 Preview 名称切换到 `MiniMax-M3.1-Flash`；能力、context 选项和 thinking effort 定义不变。显式选择其他模型的配置不受影响 | [#509](https://github.com/MiniMax-AI/minimax-code/pull/509) |
| 10-21 | ACP registry launcher | 新增单 bin 包 `@minimax-ai/code-acp`，由 ACP registry 可直接启动固定版本的 `mcode acp`；发布工作流在主包发布后按同版本选择性发布 launcher。源码已包含该包和工作流，但本文未核查 npm registry 上对应版本是否已经发布 | [#522](https://github.com/MiniMax-AI/minimax-code/pull/522) |

## 问题修复

| --- | --- | --- | --- |
