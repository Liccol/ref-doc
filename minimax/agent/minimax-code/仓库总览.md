## 定位与公开范围

MiniMax Code 是终端编码 Agent，执行命令为 `mcode`。用户描述目标后，它通过模型、文件工具、Shell 和运行时服务读取项目、修改代码、执行验证并继续任务。公开源码包括终端 TUI、无界面 exec 和 ACP 编辑器接口，也包含这些入口使用的本地运行时。

同仓 Issues 还接收桌面端产品反馈，但公开仓库不包含桌面应用源码，也不包含 Desktop HTTP front door 和仅云执行器使用的实现。跟踪时应区分源码已实现能力、桌面问题反馈、托管服务能力及仅提出的功能请求。来源：[README.md](https://github.com/MiniMax-AI/minimax-code/blob/cee079138600224e9ad4d8b954c4a4ed549e15b6/README.md)、[docs/open-source-status.md](https://github.com/MiniMax-AI/minimax-code/blob/cee079138600224e9ad4d8b954c4a4ed549e15b6/docs/open-source-status.md)。

## 核心能力

| 能力 | 用户可见内容 | 关注边界 |
| --- | --- | --- |
| 编码与验证 | 文件读取和编辑、Shell、diff 与任务验证 | 受权限、沙箱和工具配置影响 |
| TUI | 交互对话、计划、状态展示、任务中追加消息和审批 | 终端兼容与滚动/恢复行为是独立问题 |
| 无界面运行 | `mcode exec [prompt]` | 适用于脚本和 CI；需关注结果与退出状态 |
| 编辑器接入 | `mcode acp` | 客户端需支持 ACP |
| 会话管理 | 恢复会话、任务队列、分支/回退相关交互 | 区分消息历史、文件变化与子任务状态 |
| 模型接入 | MiniMax 账号 / Token Plan 与自带 key 的 custom provider | BYOK 模型与托管工具的授权不是同一件事 |
| 工具扩展 | MCP、Skills、插件、搜索、托管连接器和 mcode-tools | 发现工具、安装成功不等于实际业务调用已验证 |
| 子 Agent | runtime task services 驱动任务委派 | 不将未使用的旧 team cycle engine 当作当前执行路径 |
| 轻量对话 | `--mode lightweight` | 不发送工具 schema 和工作区指令，不能读写本地文件 |

轻量模式固定在根 Session 创建时，不能与 `--session` 或 `--continue` 合用；编码任务使用 standard 模式。来源：[README.md](https://github.com/MiniMax-AI/minimax-code/blob/cee079138600224e9ad4d8b954c4a4ed549e15b6/README.md)。能力装配和测试边界见 [docs/tui-capabilities.md](https://github.com/MiniMax-AI/minimax-code/blob/cee079138600224e9ad4d8b954c4a4ed549e15b6/docs/tui-capabilities.md)，其中历史验收信息需结合前述版本差异理解。

插件的实际管理入口与 GitHub 导入能力应查最终实现：README 对扩展方式的概述与 capability 文档对 CLI/TUI 可用入口的限制并不完全一致，不能只据“支持插件”推断任意 GitHub URL 都能在交互界面导入。

## 执行链路与模块划分

上游架构文档给出的主链路：

| `packages/local-runtime-v2/src/local/` | 进程内产品入口与本地服务契约 |
| `packages/local-runtime-v2/src/application/` | 会话、队列和用户交互应用层 |
| `packages/local-runtime-v2/src/service/` | 运行时服务实现 |
| `packages/local-runtime/` | 数据库、文件工具、权限和存储等复用设施 |
| `packages/agent-core/` | turn 执行、模型流、消息处理、工具绑定和事件桥接 |

| `packages/agent-tools/` | 工具集成、MCP disclosure 和 plugin hooks 等 |

## 安装、配置和使用

源码 Node.js 要求为 `>=22.19 <23 || >=24.2 <27`，pnpm 为 9.12.0。源码开发路径是安装依赖、构建后运行 TUI：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm mcode
```

Windows 源码构建前按 README 执行 `node scripts/check-windows-source-location.mjs`，检查本地 NTFS 与目录条件。这些是上游步骤，本次未执行安装或构建。

日常入口包括 `mcode`、`mcode exec "任务描述"`、`mcode acp`、`mcode --continue`。MiniMax 登录区分大陆与 Global；第三方服务通过 `mcode provider add` 配置，支持 `openai-completions`、`openai-responses`、`anthropic-messages`。自建模型可显式设置 context/output limit。

程序安装目录与用户数据目录应分开理解：README 将安装目录描述为 `~/.minimax-code`，用户数据默认 `~/.minimax` 或 profile 对应目录，且可被环境变量覆盖。后续跟踪配置迁移时应核对实际路径解析，避免把历史目录说明直接视为当前所有安装方式的行为。来源：[README.md](https://github.com/MiniMax-AI/minimax-code/blob/cee079138600224e9ad4d8b954c4a4ed549e15b6/README.md)、[package.json](https://github.com/MiniMax-AI/minimax-code/blob/cee079138600224e9ad4d8b954c4a4ed549e15b6/package.json)。
